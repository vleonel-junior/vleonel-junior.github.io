In the first three parts, we learned to build LTN objects and evaluate formulas, but never to make a predicate improve. That is the subject of this last part: **learning** symbols of the language (predicates, functions, constants) by using the satisfaction of a knowledge base as the training objective.

A **knowledge base** is simply a set of formulas we want to hold at the same time. Satisfying it does not mean making each formula strictly true, as in classical logic, but finding the parameters that bring each formula's degree of truth as close as possible to 1. It is a continuous optimization problem, just like minimizing a loss function, except that we maximize a degree of logical satisfaction rather than closeness to labels.

During training, what changes are the weights of the trainable predicates and functions (the neural networks we have built so far), and possibly the values of trainable constants. The logical structure of the formulas stays fixed.

## A proximity classification problem

The domain is the square $[0, 4] \times [0, 4]$: points in the plane whose two coordinates are between 0 and 4. We have 19 points and want to guess their class. Only two of them are labeled: point $a$, of class $A$, and point $b$, of class $B$. The other 17 have no label.

With two labeled examples, a classifier trained in a purely supervised way would learn nothing useful. The idea is to make up for the lack of data with **prior knowledge** about the problem, expressed as two assumptions:

- classes $A$ and $B$ are mutually exclusive: a point cannot belong to both;
- two nearby points should have the same label.

The second assumption will do most of the work. It echoes the principle of *k nearest neighbors*: a point close to $a$ probably belongs to the same class as $a$. We are going to turn it into a logical rule, which will let the model classify every point from the two labeled examples alone, without ever receiving the label of the other 17.

## The knowledge base

We define a membership predicate $C(x, l)$, where $x$ is a point and $l$ a one-hot encoded label: $[1, 0]$ for class $A$, $[0, 1]$ for class $B$. $C(x, l)$ answers the question "to what degree does point $x$ belong to class $l$?".

$C$ is a small multilayer perceptron. Its last layer uses a **softmax** rather than a sigmoid, and this choice directly encodes the first assumption. A sigmoid would evaluate each class independently; the softmax spreads a total probability mass of 1 across the classes, which makes them mutually exclusive.

The knowledge base $\mathcal{K}$ contains three formulas:

$$C(a, l_a)$$

$$C(b, l_b)$$

$$\forall x_1, x_2, l\ \Big(\mathrm{Sim}(x_1, x_2) \implies \big(C(x_1, l) \leftrightarrow C(x_2, l)\big)\Big)$$

where:

- $a$ and $b$ are the two labeled points, and $l_a$, $l_b$ the one-hot labels of $A$ and $B$;
- $x_1$ and $x_2$ are variables that range over all the points;
- $l$ is a variable that ranges over the two labels;
- $\mathrm{Sim}$ measures the similarity between two points: $\mathcal{G}(\mathrm{Sim}) : \vec{u}, \vec{v} \mapsto \exp(-\|\vec{u} - \vec{v}\|)$, the construction already met in the previous parts.

The first two formulas require $a$ to be recognized as class $A$, and $b$ as class $B$. The third encodes the proximity assumption: for every pair of points and for each label, if the two points are similar, they must get the same verdict for that label. This is what the equivalence $\leftrightarrow$ inside the implication expresses.

The goal is to learn $C$ so as to maximize the overall satisfaction of $\mathcal{K}$. Writing $\theta$ for the weights of the network that implements $C$, we are looking for:

$$\theta^\ast = \underset{\theta \in \Theta}{\mathrm{argmax}}\ \mathrm{SatAgg}_{\phi \in \mathcal{K}}\ \mathcal{G}_\theta(\phi)$$

where $\mathrm{SatAgg}$ aggregates the degrees of truth of all the formulas of $\mathcal{K}$ into a single value. We will come back to it a little further down.

Let's first define the predicates, with the same names as in the mathematical formulation:

```python
# Predicate C
class ModelC(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.elu = torch.nn.ELU()
        self.softmax = torch.nn.Softmax(dim=1)
        self.dense1 = torch.nn.Linear(2, 5)
        self.dense2 = torch.nn.Linear(5, 5)
        self.dense3 = torch.nn.Linear(5, 2)

    def forward(self, x, l):
        """x: a point, l: a one-hot label"""
        x = self.elu(self.dense1(x))
        x = self.elu(self.dense2(x))
        prob = self.softmax(self.dense3(x))
        return torch.sum(prob * l, dim=1)

C = ltn.Predicate(ModelC())

# Predicate Sim
Sim = ltn.Predicate(func=lambda u, v: torch.exp(-1. * torch.sqrt(torch.sum(torch.square(u - v), dim=1))))
```

Then the variables and constants: $x_1$ and $x_2$ range over the 19 points, $a$ and $b$ are the two labeled points, $l_a$ and $l_b$ their labels, and $l$ ranges over the two possible labels.

LTN does not implement it as a standalone operator, but builds it from two known operators, following the classical equivalence $p \leftrightarrow q \equiv (p \implies q) \land (q \implies p)$. `ltn.fuzzy_ops.Equiv` takes the t-norm and the implication to use for this construction.

```python
Forall = ltn.Quantifier(ltn.fuzzy_ops.AggregPMeanError(p=2), quantifier="f")
Exists = ltn.Quantifier(ltn.fuzzy_ops.AggregPMean(p=6), quantifier="e")
```

## From closed formulas to a loss function

When $\mathcal{K}$ contains several formulas, their degrees of truth must be aggregated into a single value: that is the role of $\mathrm{SatAgg}$. It only applies to **closed formulas**, that is, formulas with no free variable: all their variables have been captured by a quantifier. If a formula still contained a free variable, its degree of truth would not be a single number but a tensor of values, one per value of the variable, and $\mathrm{SatAgg}$ would not know which one to keep.

A few examples to pin down this criterion:

- $\text{IsFriendOf}(x, y)$ has two free variables: it is not closed, and evaluating it gives a matrix.
- $\forall x\, \text{IsFriendOf}(x, y)$ is not closed either: $y$ remains free, and the result is a vector, one value per $y$.
- $\forall x\, \forall y\, \text{IsFriendOf}(x, y)$ is closed: evaluating it gives a scalar.
- $\exists y\, \forall x\, \text{IsFriendOf}(x, y)$ is closed too. All that matters is that every variable is quantified, not the order or the type of the quantifiers.

In our base, $C(a, l_a)$ and $C(b, l_b)$ are closed from the start, since they only contain constants: there is nothing to quantify. The third only becomes closed thanks to the $\forall x_1, x_2, l$ that captures its three variables.

In LTN, $\mathrm{SatAgg}$ is available through `ltn.fuzzy_ops.SatAgg`, whose constructor takes an aggregation operator. Here again we recommend `pMeanError`, the same as for $\forall$, and it is the default. $p$ plays the same role as for quantifiers: the lower it is, the closer the aggregation gets to a mean of the formulas; the higher it is, the closer it gets to the worst formula of $\mathcal{K}$. `SatAgg` directly accepts `LTNObject`s: no need to go through `.value`.

Finally, we want to **maximize** satisfaction, whereas PyTorch optimizers **minimize** a loss. We therefore define the loss as $1 - \mathrm{SatAgg}$: minimizing it is exactly the same as maximizing satisfaction.

Before starting training, let's follow the computation of the third formula on a case small enough to be done by hand. We use the product configuration:

- Reichenbach implication: $u \implies v = 1 - u + uv$;
- equivalence: $\mathrm{Equiv}(u, v) = (1 - u + uv)(1 - v + uv)$, the product of the two implications.

In these formulas, $u$ and $v$ are **scalars**: individual degrees of truth in $[0, 1]$.

**The data**

We take 3 points instead of 19:

$$q_0 = (0, 0) \qquad q_1 = (3, 3) \qquad q_2 = (0.1,\ 0.1)$$

$x_1$ and $x_2$ range **independently** over this same domain, so any formula $\phi(x_1, x_2)$ is computed over the Cartesian product, a $3 \times 3$ grid indexed by $(i, j)$.

**Step 1: Sim(x1, x2)**

$$\mathrm{Sim}[i, j] = \begin{pmatrix} 1 & 0.014 & 0.868 \\ 0.014 & 1 & 0.017 \\ 0.868 & 0.017 & 1 \end{pmatrix}$$

The matrix is symmetric, and its diagonal is 1 since each point is identical to itself. $q_0$ and $q_2$ are very close, $q_1$ is far from both.

**Step 2: C(x, l), the confidence predicate**

$C$ is a function of **a single point** and a label. Suppose the network, not yet trained, gives the following confidences (one row per point, one column per label):

$$C(x, l) = \begin{pmatrix} 0.9 & 0.1 \\ 0.2 & 0.8 \\ 0.5 & 0.5 \end{pmatrix}, \qquad x \in \{q_0, q_1, q_2\}$$

$x_1$ and $x_2$ range over the same domain with the same predicate: $C(x_1, l)$ and $C(x_2, l)$ are the same function, evaluated at different indices ($i$ for $x_1$, $j$ for $x_2$). For a fixed label, we therefore extract a **vector** indexed by the points:

$$c_A = \big(C(q_0, A),\ C(q_1, A),\ C(q_2, A)\big) = (0.9,\ 0.2,\ 0.5)$$

$$c_B = \big(C(q_0, B),\ C(q_1, B),\ C(q_2, B)\big) = (0.1,\ 0.8,\ 0.5)$$

Thanks to the softmax, the two columns sum to 1: $c_B = 1 - c_A$ element-wise.

**Step 3: Equiv(C(x1, l), C(x2, l))**

$$M_l[i, j] = \mathrm{Equiv}\big(c_l[i],\ c_l[j]\big), \qquad (i, j) \in \{0, 1, 2\}^2$$

$u = c_l[i]$ and $v = c_l[j]$ are two values **of the same vector**, taken at two indices. For $l = A$, with $c_A = (0.9,\ 0.2,\ 0.5)$:

| $(i, j)$ | $(u, v)$ | $u \implies v$ | $v \implies u$ | $\mathrm{Equiv}$ |
|---|---|---|---|---|
| $(0, 0)$ | $(0.9,\ 0.9)$ | $0.91$ | $0.91$ | $0.8281$ |
| $(0, 1)$ | $(0.9,\ 0.2)$ | $0.28$ | $0.98$ | $0.2744$ |
| $(0, 2)$ | $(0.9,\ 0.5)$ | $0.55$ | $0.95$ | $0.5225$ |
| $(1, 1)$ | $(0.2,\ 0.2)$ | $0.84$ | $0.84$ | $0.7056$ |
| $(1, 2)$ | $(0.2,\ 0.5)$ | $0.90$ | $0.60$ | $0.5400$ |
| $(2, 2)$ | $(0.5,\ 0.5)$ | $0.75$ | $0.75$ | $0.5625$ |

The matrix is symmetric, since $\mathrm{Equiv}(u, v) = \mathrm{Equiv}(v, u)$ by construction:

$$M_A = \begin{pmatrix} 0.8281 & 0.2744 & 0.5225 \\ 0.2744 & 0.7056 & 0.5400 \\ 0.5225 & 0.5400 & 0.5625 \end{pmatrix}$$

**Why is $M_B = M_A$?** Since $c_B = 1 - c_A$, we have $M_B[i, j] = \mathrm{Equiv}(1 - c_A[i],\ 1 - c_A[j])$. Now:

$$\mathrm{Implies}(1 - u,\ 1 - v) = 1 - (1 - u) + (1 - u)(1 - v) = 1 - v + uv = \mathrm{Implies}(v, u)$$

so:

$$\mathrm{Equiv}(1 - u,\ 1 - v) = \mathrm{Implies}(v, u) \times \mathrm{Implies}(u, v) = \mathrm{Equiv}(u, v)$$

The two matrices have exactly the same 9 values, for an algebraic reason and not by coincidence.

**Step 4: Implies(Sim(x1, x2), Equiv(C(x1, l), C(x2, l)))**

$\mathrm{Sim}[i, j]$ and $M_l[i, j]$ are indexed by the same $(i, j)$ grid, since both come from the grounding of $x_1$ and $x_2$. The implication is therefore computed entry by entry:

$$N_l[i, j] = \mathrm{Implies}\big(\mathrm{Sim}[i, j],\ M_l[i, j]\big) = 1 - \mathrm{Sim}[i, j] + \mathrm{Sim}[i, j] \cdot M_l[i, j]$$

$$N_A = N_B = \begin{pmatrix} 0.8281 & 0.9896 & 0.5855 \\ 0.9896 & 0.7056 & 0.9924 \\ 0.5855 & 0.9924 & 0.5625 \end{pmatrix}$$

The rule can be read directly: when two points are far apart ($\mathrm{Sim}$ close to 0), the implication is almost true whatever their disagreement, because the rule says nothing about them. When they are close, the agreement of their confidences decides.

**Reading one entry**

Each entry $N_l[i, j]$ answers a precise question, fixed by the three indices: taking $x_1 = q_i$, $x_2 = q_j$ and the label $l$, to what degree does the axiom "if they are similar, they get the same confidence for this label" hold?

Take $N_A[0, 2]$:

1. We instantiate $x_1 = q_0$, $x_2 = q_2$ and $l = A$.
2. $\mathrm{Sim}(q_0, q_2) = 0.868$: the two points are very close.
3. $\mathrm{Equiv}(C(q_0, A),\ C(q_2, A)) = \mathrm{Equiv}(0.9,\ 0.5) = 0.5225$: the network gives $q_0$ 90% confidence for class $A$, but only 50% to $q_2$. The two verdicts disagree.
4. $\mathrm{Implies}(0.868,\ 0.5225) = 0.5855$.

A value of $0.5855$, far from 1, signals a violation of the axiom: two nearby points should get close confidences for class $A$. This kind of entry is what will produce a strong gradient signal, pushing the network to bring $C(q_0, A)$ and $C(q_2, A)$ closer.

**Step 5: the ∀ quantifier**

`Forall([x1, x2, l], …)` aggregates the $3 \times 3 \times 2 = 18$ entries with `pMeanError` and $p = 2$:

$$\mathrm{pME} = 1 - \left(\frac{1}{18} \sum_{l} \sum_{i, j} \big(1 - N_l[i, j]\big)^2\right)^{1/2}$$

| $(i, j)$ | $N_l[i, j]$ | $1 - N_l[i, j]$ | $(1 - N_l[i, j])^2$ | entries per label |
|---|---|---|---|---|
| $(0, 0)$ | $0.8281$ | $0.1719$ | $0.029550$ | 1 |
| $(1, 1)$ | $0.7056$ | $0.2944$ | $0.086671$ | 1 |
| $(2, 2)$ | $0.5625$ | $0.4375$ | $0.191406$ | 1 |
| $(0, 1)$, $(1, 0)$ | $0.9896$ | $0.0104$ | $0.000109$ | 2 |
| $(1, 2)$, $(2, 1)$ | $0.9924$ | $0.0076$ | $0.000058$ | 2 |
| $(0, 2)$, $(2, 0)$ | $0.5855$ | $0.4145$ | $0.171834$ | 2 |

For one label, the sum is $0.307627 + 2 \times 0.172001 = 0.651629$, and since $N_A = N_B$, it is counted twice:

$$\mathrm{pME} = 1 - \left(\frac{1.303258}{18}\right)^{1/2} = 1 - 0.2691 = 0.731$$

Notice the diagonal. One might think that comparing a point with itself is trivially true, but that is not the case in fuzzy logic: $\mathrm{Equiv}(u, u) = (1 - u + u^2)^2$ only equals 1 when $u$ is 0 or 1. For $q_2$, whose confidence is $0.5$, entry $(2, 2)$ is only $0.5625$, and it is even the worst entry in the table. The training code below aggregates over all pairs, diagonal included: these entries therefore push the network toward **clear-cut** verdicts, close to 0 or 1, rather than undecided confidences.

**The loss**

The loss finally combines the three formulas of $\mathcal{K}$:

$$\text{loss} = 1 - \mathrm{SatAgg}\big(C(a, l_a),\ C(b, l_b),\ 0.731\big)$$

## Why compare every pair?

One could imagine a simpler rule: compare each unknown point with $a$ and $b$ only, and infer its class from that, like a nearest-neighbor algorithm with two reference neighbors:

$$\forall x\ \big(\mathrm{Sim}(x, a) \implies C(x, l_a)\big) \qquad \forall x\ \big(\mathrm{Sim}(x, b) \implies C(x, l_b)\big)$$

This rule would only light up the points close enough to the two lamps $a$ and $b$: a point too far away would stay in the dark, even if surrounded by points that are already well lit. The rule of $\mathcal{K}$ compares **every pair**: each lit point in turn lights up its neighbors, and the light spreads from one end of the point cloud to the other, even very far from $a$ and $b$, as long as there is a path of successive proximities.

This is what justifies the computational cost, $19 \times 19$ pairs instead of $19 \times 2$: it is not needless overhead, it is what lets information flow through the whole proximity graph.

## Training

Each iteration computes the degrees of truth of the three formulas of $\mathcal{K}$ (*forward* pass), then adjusts the weights of $C$ by backpropagation to reduce the loss (*backward* pass).

```python
# by default, SatAgg uses pMeanError
sat_agg = ltn.fuzzy_ops.SatAgg()

# we learn the parameters of the predicate C
optimizer = torch.optim.Adam(C.parameters(), lr=0.001)

for epoch in range(2000):
    optimizer.zero_grad()
    loss = 1. - sat_agg(
        C(a, l_a),
        C(b, l_b),
        Forall([x1, x2, l], Implies(Sim(x1, x2), Equiv(C(x1, l), C(x2, l))))
    )
    loss.backward()
    optimizer.step()
    if epoch%200 == 0:
        print("Epoch %d: Sat Level %.3f "%(epoch, 1 - loss.item()))
print("Training finished at Epoch %d with Sat Level %.3f" %(epoch, 1 - loss.item()))
```

## Working in mini-batches

In most learning tasks, we work in batches rather than with the whole dataset at each iteration, especially when it is too large to be processed at once.

In LTN, this requires no special mechanism: we simply **reground the variables** with different values at each step. In PyTorch, these values usually come from a `DataLoader`, which splits the dataset and hands out the subsets over the iterations.

Let's take the same problem with 10,000 random points. $a$ and $b$ are deliberately placed fairly far apart, to keep the example readable.

```python

points[-1] = torch.tensor([3., 3.])

points_a = torch.tensor([3., 3.])
```

We define a data loader that returns a batch of points at each iteration, with a batch size and optional shuffling at each epoch. The training principle stays the same: the same three formulas, aggregated by `SatAgg`, then backpropagation. The only difference is that $x_1$ and $x_2$ now hold 512 different points at each iteration.

```python
# redefine C to reset its weights
C = ltn.Predicate(ModelC())

# data loader that creates the batches
class DataLoader:
    def __init__(self,
                 dataset,
                 batch_size=1,
                 shuffle=True):
        self.data = dataset
        self.batch_size = batch_size
        self.shuffle = shuffle

    def __len__(self):
        return int(np.ceil(self.data.shape[0] / self.batch_size))

    def __iter__(self):
        n = self.data.shape[0]
        idxlist = list(range(n))
        if self.shuffle:
            np.random.shuffle(idxlist)

        for _, start_idx in enumerate(range(0, n, self.batch_size)):
            end_idx = min(start_idx + self.batch_size, n)
            batch_points = self.data[idxlist[start_idx:end_idx]]

            yield batch_points

train_loader = DataLoader(points, 512)

sat_agg = ltn.fuzzy_ops.SatAgg()
optimizer = torch.optim.Adam(C.parameters(), lr=0.001)

for epoch in range(100):
    for (batch_idx, (batch_points)) in enumerate(train_loader):
        x1 = ltn.Variable("x1", batch_points)  # reground the variables
        x2 = ltn.Variable("x2", batch_points)  # with the current batch
        optimizer.zero_grad()
        loss = 1. - sat_agg(
            C(a, l_a),
            C(b, l_b),
            Forall([x1, x2, l], Implies(Sim(x1, x2), Equiv(C(x1, l), C(x2, l))))
        )
        loss.backward()
        optimizer.step()
    if epoch%10 == 0:
        print("Epoch %d: Sat Level %.3f "%(epoch, 1 - loss.item()))

print("Training finished at Epoch %d with Sat Level %.3f" %(epoch, 1 - loss.item()))
```

## Key takeaways

- A **knowledge base** is a set of closed formulas; learning it means finding the parameters that maximize their satisfaction.
- **`SatAgg`** aggregates the satisfaction of the formulas into a single value, and the loss is $1 - \mathrm{SatAgg}$.
- Only the **weights** of trainable predicates, functions and constants change; the logical structure stays fixed.
- Prior knowledge, such as "two nearby points have the same class", makes it possible to learn from very few labels, because information **spreads** through every pair.
- Working in **mini-batches** simply means regrounding the variables at each iteration.

This part wraps up the presentation of LTN's mechanisms. The same principle, logical knowledge turned into a loss function, goes much further: in the case study in my repository, an LTN learns to recognize handwritten digits without ever seeing their labels, from the sum of two digits alone.
